3. 核心鏈前後對照

環節0.0.4 斷在哪0.0.5 怎麼接
① 辨識畫像庫只有 PS／AI／PR；子字串比對，Final Cut Pro、「Pro Max」被認成 Premiere；「PS5」會被當成修圖畫像 2.0：工作類型 × 0–3 等級，3D 軟體 10 套；別名表＋整詞比對（容許黏著版本號，如 Blender4.2）；模糊時出消歧義卡；模型可給目錄外軟體暫定等級
② 需求 → 權重模型的權重建議一輪輪疊加；刪掉需求不退回；「常帶出門」不改權重；拖滑桿後全部鎖死權重帳本：每輪從後台基準重新推導、每一分都有來源句；13 列訊號點數 × 強度係數；只鎖使用者真的拖的那一維；「恢復系統建議」
③ 大維度 → 細項子權重寫死；Office、VRay、Blender、NPU 沒進評分細項實測已匯入；畫像等級經中央換算表變成子權重向量，再依主次占比與強度混合；覆蓋率不足的細項自動停用
④ 分數正規化用「距第一名 %」；填補值不標；性價比每輪跳動；同分按 id 字母序全庫百分位正規化；填補值標「估計」並用同類保守值；性價比改同價位期望差；平手門檻內依使用者最重視的維度決勝；每台附 breakdown

⑥ 追問題目不管會不會改變結果都問先模擬每個答案會不會改變前幾名，不會就不問並說明；上限 3 題、連續 2 題、忽略冷卻

8. 已知限制

  • 資料是模擬的：重量大量填補、GJS0001 售價偏低、遊戲幀數排序不可靠；黃金樣本測試綁定目前這份 CSV，換真實資料（資料清理/laptops_clean.csv）時要重跑。
  • 平手門檻、訊號點數、強度係數、換算表、填補比例等數值都是起始值，待真實使用者校準。
  • 未做：點擊統計 click_stats（仍用平均）、追問「不確定」選項 followup.unsure、前端子權重編輯介面。
  • 追問模擬不重算子權重（只有剪輯強度卡受影響，價值會略為低估）。
  • 多 worker 部署時，後台只改單台實測又只在一個行程重算，其他行程的正規化快取要等資料或公式版本更新才失效。
  • 前端打包 672 KB，超過 Vite 建議的 500 KB，之後可把後台頁改成動態載入。

9. 怎麼啟動與測試（Mac）

cd /Users/m/Desktop/Laptopbuyingassisstant/system-v0.0.5
lsof -nP -iTCP:5433 -sTCP:LISTEN          # 確認 5433 沒有別的 PG（v0.0.4 也用 5433）
pg_ctl -D data/pg-mac -o "-p 5433 -k /tmp" -l logs/postgres-mac.log -w start
cd backend && UV_PROJECT_ENVIRONMENT=.venv-mac uv run --no-sync uvicorn app.main:app --port 8010
# 瀏覽器開 http://127.0.0.1:8010 ，後台 /admin；用完 pg_ctl -D data/pg-mac stop

# 測試（不需要 PostgreSQL）

cd frontend && npx tsc --noEmit && npm test && npm run build                                # 243 passed
