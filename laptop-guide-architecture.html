系統脈絡圖

System Context：誰在用系統？系統跟外面哪些東西打交道？

重點說明

  • 系統只有兩種使用者：前台消費者和後台管理員。管理員分角色，observer 只能看，不能改（api.py:85、api.py:162）。
  • 外部只會呼叫 LLM，實際只用到兩個「槽位」：nlu（需求理解）和 reply（回覆生成）。test_connection 是後台按「測試」才會觸發的連線檢查。
  • 程式裡沒有任何電商、價格或影片的外部 API。購買連結只是存在資料庫裡的網址，由瀏覽器自己打開。
  • 軟體預填（/admin/software/search-prefill）只對草稿裡第一個來源網址發一次 GET，看能不能連上，不會抓內容。來源網址實際有哪些值 待確認。

容器 / 部署架構圖

系統實際跑在哪裡？啟動時發生什麼事？
flowchart

重點說明

  • 整套系統只有 2 個執行程序：PostgreSQL 和 uvicorn。uvicorn 同時負責 API 和前端網頁，所以沒有 Nginx、Redis、訊息佇列，也沒有獨立的前端伺服器。
  • 前端已預先建置成 frontend/dist，平常啟動不需要 Node.js。
  • 埠號提醒：.env 預設 8000，但 Vite 開發代理寫死 8010（vite.config.ts）。README 也提醒了這點。
  • Linux 雲端部署、反向代理、HTTPS 和行程守護，README 寫的是「需要另行設定」→ 待確認，目前沒有實作。
  • 一鍵關閉系統.bat 的關閉流程我沒有細讀 → 待確認。

主要資料表（models.py）

分組資料表
使用者users、user_settings、visitors（只有後台總覽會讀，寫入位置 待確認）

重點說明

  • 符合「程式碼決定事實」：篩選（domain.snapshot）、評分（scoring）、動作決策（action_for_count）和選卡（cards）都是確定性程式碼。LLM 只做兩件事：把自然語言轉成 ops，以及把 facts 轉成回覆文字。
  • cards._pick_followup_card_model 是 stub，切到 model 策略也會退回 rules（cards.py:737）。
  • model_configs.api_key_enc 名稱看起來是「加密」，但程式碼找不到任何加密邏輯，seed.py:250 是直接把 .env 的金鑰寫進去 → 是否應該加密，待確認。

關鍵資料流：使用者送出一句話

入口 POST /api/conversations/{cid}/messages → pipeline.run_turn()；圓圈編號對應 trace.ts 的 11 步
sequenceDiagram

重點說明

  • 同一條 run_turn 管線還有兩個入口：/profile（修改或刪除需求）和 /weights/apply（手動調權重）。這兩個都用 skip_nlu 跳過 LLM，只重新篩選和評分，然後照樣生成回覆。
  • 兩個降級點：NLU 失敗改用 heuristic_ops，回覆生成失敗改用 fallback_reply。所以沒有金鑰也能跑完整流程，只是理解能力比較弱。
  • trace.ts 定義了「SSE 推送」這個類型，但後端沒有 SSE 或串流端點，目前是一次回傳整包 JSON。SSE 是規劃中還是已經放棄 → 待確認。
  • 步驟 ①「鎖發送」應該是在前端實作，我沒有追進 UserApp.tsx 的細節 → 待確認。
