AI 筆電選購助手 · 可切換模組總覽（v1.0.25）

2026-11-07 · 依 laptop-assistant-v1.0.25 原始碼整理：哪些模組已經能切換、各模組的介面與資料契約、哪些切換最重要

一句話：「流程」與「右欄畫面」兩個程式型模組已經能完整切換；對推薦品質影響最大、卻還不能切換的是排序／權重引擎，左欄對話區也還沒插槽化。

一、整體地圖

已可切換 還不能切換 固定（共用） － － 後台設定指向

另外還有 178 個功能開關（packages/contracts/src/flags.ts，9 個群組），它們是開或關的細節，不算「可整套替換的模組」。

模組的兩種切換方式

種類意思包含
程式型換方案等於換一支程式，可以有完全不同的流程、畫面與互動① 流程方案、② 候選池方案
資料型程式不變，只換一組參數③ 顯示方案、④ 動效方案、①-a 提示詞、①-b 供應商

二、各模組的介面與資料契約

已可切換① 流程方案（後端，處理一句話）

輸入 SchemeContextcfg 設定、state 對話狀態、input、model(step)、log、lap、deadlineAt／remainingMs()、runId
→
方案 run(sc)自己決定呼叫 AI 幾次、什麼順序、出錯怎麼補救；不能碰資料庫
→
輸出 SchemeOutcomeaction、reply、cards、snapshot、weightTrace、nlu、askTrace、unknown、unclear、followup、trace
項目內容
已登錄方案baseline：理解 1 次 → 意圖路由 → 需求與權重 → 排序 → 追問 → 回覆 1 次
single-call：只呼叫 AI 1 次（理解＋回覆草稿一起做），AI 看得到前 5 名，不出追問卡
介面 TurnSchemeid、name、desc、steps[]、run(sc)
步驟 SchemeStepid（例如 understand）、role（nlu／reply）、title、desc、vars（提示詞變數）、defaultPrompt
輸入（主機 → 方案）cfg、state（已還原、已去掉下架機型，方案可直接改）、input、model(step, enabled)（取模型與提示詞，已帶好逾時）、log、lap、deadlineAt、remainingMs()、runId、conversation
輸出（方案 → 主機）action、reply、replySource（model／template）、cards、snapshot、weightTrace、nlu、askTrace、unknown、unclear、followup、echoUserMessage、trace
硬規定方案不能 import 資料庫；所有存檔由主機做；私有狀態放 state.ext[方案id]；剩不到 1000 毫秒就不呼叫 AI，改走程式保底
設定settings.turn_scheme = { activeId }，預設 baseline；找不到就退回 baseline
紀錄（供比較）runs.scheme_id、各步耗時、runs.trace；llm_calls 記 scheme_id、step、attempt、prompt 原文、output 原文
程式位置apps/api/src/scheme.ts、apps/api/src/schemes/、packages/contracts/src/scheme.ts

已可切換①-a 提示詞版本

  • 資料表 prompts：(scheme_id, slot＝步驟id, version) 唯一，加上 body、active
  • 每個方案、每個步驟各自有版本，可以單獨切換
  • 沒存過就用程式帶的 defaultPrompt

已可切換①-b AI 供應商

  • 資料表 model_providers：slots: ("nlu"｜"reply")[]、enabled
  • 方案的每個步驟依宣告的 role 取「第一家啟用的」
  • 切換方式＝啟用／停用供應商

已可切換② 候選池方案（前端，右欄結果區）

輸入 PoolInput（只讀）mode、flags、params、snapshot、conversation、busy、byId、prefs、dims、decor、photoPool…
→
方案 Pane整個右欄畫面；只用 usePool() 取資料，不能直接打 API
→
動作 PoolActions＋標籤排除、對比、收藏、改需求、套權重…；貼 data-motion 標籤讓動效找到
項目內容
已登錄方案classic：原本的分組清單
gallery：圖片卡＋特色短句、全螢幕對比頁＋自動圖表（雷達圖、長條圖）
模組 PoolSchemeModuleid、name、desc、Pane、params、可選 Compare（取代對比抽屜內容）、compareFullscreen
輸入（殼 → 方案）mode（live／replay）、flags、params、snapshot（formal／edge／out／total／funnel）、conversation、busy、lastExcluded、favoriteIds、byId、prefs、dims、decor（只有重播會給）、photoPool；另有 on(flag) 判斷開關
動作（方案 → 狀態中心）setExcluded、setCompared、clearCompare、setFavorite、editRequirement、removeRequirement、setFilter、applyWeights、resetWeights、track、listLaptops、getLaptop、getHome（classic 專用）、openDetail、openDrawer、toast、setPrefs
參數 ParamSpecdefaults、normalize（遇到任何輸入都不能丟錯）、errors（中文錯誤）、form（custom-display，或 number／boolean／text／select／multi 欄位自動產生表單）
動效標籤約定data-motion="card"＋data-laptop-id、count、body、power、rank；需求標籤 data-req-id
設定settings.pool_scheme = { activeId, params: { 方案id: 參數 } }（classic 的參數仍存在 settings.display）
紀錄與重播每輪把方案 id（非 classic 時連同參數）寫進 runs.snapshot，後台重播時插回同一個方案
隔離規則方案不能 import shared/api、不能直接呼叫 useApp()、不能載入 gsap；最外層要有 u-results；方案出錯時退回 classic
程式位置apps/web/src/user/pools/（contract.ts、index.ts、PoolHost.tsx、README.md）、packages/contracts/src/pool.ts

已可切換③ 候選機型顯示方案

DisplayScheme：

  • browse.grouped、browse.groups[]（熱門／價格區間，各有 preview 台數）
  • popularIds[] 熱門機型順序
  • results[]：top／alts／rest／popular／edge／asked／out／excluded，每組有 on、title、count

存在 settings.display = { activeId, schemes }；現在是 classic 的專屬參數。

已可切換④ 動效方案

MotionScheme：

  • enabled（關閉時完全不載入動畫程式）、speed、autoOpenWeights
  • steps：10 段動畫，每段有 on／duration／delay／stagger／ease

存在 settings.motion = { activeId, schemes }；動畫事件 MotionEvent 由伺服器算，前端只播放。

還不能切換尚未模組化的部分

模組現況
排序／權重引擎packages/engine 是純函式但只有一套；SchemeOutcome.snapshot 已預留位置，之後可以在引擎前面加「排序方案」介面
左欄對話區ChatPane 維持原樣；M 已決定之後照候選池的插槽機制做
意圖分類詞庫與文案（settings.intent）可以在後台改，但分類程式只有一套

三、哪些切換比較重要

排名模組重要性原因
1① 流程方案（含提示詞）★★★★★直接決定「系統聽不聽得懂用戶」，也就是專案的唯一標準。紀錄已經存齊（提示詞、原文、耗時），可以並排比較。
2排序／權重引擎 未做★★★★★產品方向是「依每位用戶的權重排序是核心」，但目前只有一套，是最值得補上的下一個可切換模組。
3② 候選池方案★★★★☆用戶實際看到、實際操作的地方，最適合拿去找真實用戶做 A/B 測試。
4③ 顯示方案★★☆☆☆只能調分組與台數，已經併進 classic。
5④ 動效方案★★☆☆☆影響體驗的質感，不影響推薦對不對。
6①-b AI 供應商★☆☆☆☆M 之前已經定為「不重要」。
已知限制：single-call 方案還沒用真實模型驗收過；gallery 方案 371 台裡只有 5 台有真實圖片，其他機型借用這 5 張並標「示意圖」，只能用來測版面與互動。
