v10demo 與 system 0.0.3：介面、功能與細節差異

同一個產品「AI 筆電選購助手」目前有兩套實作。v10demo 是三個靜態檔案組成的設計示範（index.html、engine.js、admin.html）；system 是 React＋FastAPI＋PostgreSQL 的正式系統。本報告逐模組比較兩者在使用者端與管理後台的差異，並依產品負責人 M 的方向（權重是核心、以 system 為主體）提出具體的建議做法。10-30 改版新增「核心」6 章，深入分析權重、分數計算、高級權重、軟體畫像與推薦理由。

一頁看懂：兩個版本的本質差異

10-30 改版：依 M 的產品方向重新評價

  • 權重是系統的核心。分析需求 → 算出這位使用者的權重 → 計算每台筆電的得分 → 推薦最適合的。system 的分數排序是對的方向；v10 那種「4K 匯出 7.5 分鐘以內」的硬門檻太武斷，不再當成優點。
  • 對話與追問以 system 為主：接上 LLM、每條規則都有開關，才能測出哪種做法真的有效。
  • v10 的模擬資料、權限、模型是 demo 的本質，不算缺點；system 還沒完成的開關、閾值、告警、token 統計，是尚未完成，不是「假功能」。
  • 不做確認卡、不做深色模式、不移植 v10 的草稿／回歸／發佈流程（版本另外管理）；鏈路與日誌是基礎能力，排在後面；後台首頁等功能完成後再做。
  • 新增「核心」6 章：總覽與施工順序、權重系統、分數計算、高級權重、軟體畫像（3ds Max）、推薦理由與追問設計。每章都有「我的建議做法」。
v10demo · 互動細節的參考樣本

它的價值在表達：先複述你說的話、追問會說還剩幾題、能跳過、推薦時說清楚「這台好在哪、你要接受什麼、為什麼不是別台」。這些表達方式值得借用，但它背後的「硬門檻＋規則」推薦邏輯不是我們要的方向。

system 0.0.3 · 正式產品的底座

它有對的骨架：LLM 理解需求、權重＋多維度評分、軟體畫像、卡片題庫、真實資料庫與權限。現在最大的缺口是「權重 → 分數 → 理由」這條鏈還沒接完整：有些需求沒有影響權重（例如「常帶出門」「剪輯強度」），推薦理由是模板字，部分後台參數還沒被讀取。

總結建議：以 system 為主體往下做。第一優先是把核心鏈接完整：需求 → 權重（含高級細項與軟體畫像）→ 分數 → 由程式算出的推薦理由。v10 只借用它的表達方式和互動細節。
