v10demo 與 system 0.0.3：介面、功能與細節差異

同一個產品「AI 筆電選購助手」目前有兩套實作。v10demo 是三個靜態檔案組成的設計示範（index.html、engine.js、admin.html）；system 是 React＋FastAPI＋PostgreSQL 的正式系統。本報告逐模組比較兩者在使用者端與管理後台的差異，指出各自的長處、system 中「看起來有、其實沒作用」的地方，並建議整合方向與可做成開關的項目。

一頁看懂：兩個版本的本質差異

v10demo · 設計得很完整的示範

它是一套「懂行店員」：先複述你說的話，翻譯成實測門檻，例如「剪 4K → 匯出 7.5 分鐘以內」。只問會改變結論的問題，推薦前會確認一次，再用實測數字說明「這台為什麼適合你、你要接受什麼」。後台是營運工作台，有待辦、徽章，每個數字都能點進去看對話。改規則要先存草稿、預覽影響、跑回歸測試、寫明原因才能發佈，而且能回滾。但是資料、權限、模型調用全部是模擬的。

system 0.0.3 · 真的能跑的工程底座

它有真實的登入與角色、PostgreSQL、CSV 匯入與版本回滾、可以接上的 LLM 供應商、軟體畫像審核流程、變更紀錄，以及 GSAP 動畫事件佇列。但推薦是「分數排序表」，理由大多是模板字。追問沒有上限，也沒有確認步驟。後台偏向攤開資料表，而且有不少「看起來有、其實沒作用」的地方：規則開關、5 個閾值、告警、token 統計、分數一致性檢查。

總結建議：以 system 的資料層與權限為底座，把 v10 的互動流程、推薦內容邏輯、後台工作流程移植過去。動手移植之前，先修好 system 的「假功能」，因為它們違反了專案原則「程式碼決定事實」。
