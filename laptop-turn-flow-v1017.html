一句話的旅程

你在筆電選購助手輸入一句話之後，系統裡的每個角色各自做了什麼、拿了什麼資料、花了多久。所有數字都來自用 v1.0.17 實際重跑的結果。

版本 v1.0.17 例句：「想買一台打遊戲的筆電，8 千左右」 實測 2026-11-06 總時間 3.87 秒 真的呼叫 DeepSeek 2 次

先認識 4 個角色

你（瀏覽器）

你看到的網頁。負責把你打的字送出去，收到結果後畫出卡片和回覆。

伺服器（程式）

像店裡的總管。所有判斷和計算都是它做的：讀設定、整理需求、幫 371 台打分數、決定怎麼回。

資料庫

像一個大型 Excel 檔，裡面有很多張「工作表」（叫做「表」）：設定、對話、訊息、每一輪紀錄……。只負責存和拿，不做判斷。

AI（DeepSeek）

外面請來的語言專家，透過網路聯絡。只做兩件事：把你的話翻成需求清單、把算好的結果寫成一段話。不負責算分數。

伺服器和資料庫之間用一種叫 SQL 的指令溝通（像「去設定表拿名稱是 flags 的那一列」）；伺服器和 AI 之間用 HTTP 請求溝通（像寄一封信過去、等回信）。下面每一步都會把原文翻成白話。

名詞小辭典

表（工作表）
資料庫裡的一張表格，像 Excel 的一個分頁。例如 settings 是「設定表」、messages 是「訊息表」。
列、欄
一列是一筆資料（例如一則訊息），一欄是一種資訊（例如「文字」「建立時間」）。
SQL
跟資料庫說話的指令語言。select＝拿、insert＝新增、update＝修改、from＝從哪張表、where＝條件。
$1、$2（參數）
指令裡的「填空格」。程式先把指令和要填的值分開送，資料庫自己填進去。這樣即使你打的字裡有奇怪符號，也不會被當成指令執行，比較安全。
交易（begin／commit）
把好幾個寫入綁在一起：要嘛全部成功、要嘛全部取消。不會出現「訊息存了、紀錄沒存」的半套狀態。
HTTP 請求
電腦之間透過網路「寄信、回信」的格式。POST 表示「我要送資料給你處理」。
Cookie
瀏覽器幫網站記住的小紙條。這裡存一個訪客編號，伺服器靠它認出「這是同一個人」。
提示詞
送給 AI 的完整文字：固定的工作說明，加上這次的資料（你的話、需求檔案、事實清單）。
token
AI 計算字數的單位，大約一個中文字算 1 個左右。AI 依 token 收費。
JSON
一種程式之間交換資料的格式，用 { } 和 [ ] 包起來，像 {"預算": 8000}。
記憶體
伺服器桌上的備忘。開機時把 371 台機型抄一份放在這裡，之後不用每次去資料庫拿。
毫秒（ms）
千分之一秒。1,000 ms＝1 秒。
權重
7 個評分項目各占多少比重，加起來是 100。例如性能 39 表示性能占你考量的 39%。
硬條件／軟條件
硬條件不符合就直接淘汰（例如「一定要 Mac」）；軟條件只影響排名、不淘汰。

資料怎麼來的：把開發資料庫完整複製成暫時的資料庫，用 v1.0.17 原始程式（沒有改任何一行）在上面重跑：開新對話 → 說「想買一台打遊戲的筆電，8 千左右」 → 手動調權重。過程中攔下每一條送給資料庫的 SQL 和每一次送給 DeepSeek 的 HTTP 請求（金鑰已遮蔽），AI 是真的呼叫。跑完已刪除暫時資料庫；專案資料夾和原本的資料庫都沒有動。
